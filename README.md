# Experiment Assignment Service

A small service that answers one question on every page load — "which variant should
this visitor see?" — deterministically and off the database, plus the tracking and
reporting needed to tell which variant is winning. Built for a take-home assignment;
see [`DESIGN.md`](./DESIGN.md) for the full design document (architecture, determinism,
scale, failure modes, and the trade-offs made under a 24h budget).

## What's here

- **Assignment** (`GET /assign`) — hash-bucket based, deterministic, stateless, reads
  only an in-memory config cache (never Postgres on this path).
- **Tracking** (`POST /track/exposure`, `POST /track/conversion`) — durable, deduped
  via DB unique constraints.
- **Config API** (`POST /sites`, `POST /experiments`, `GET /experiments/:id`,
  `PATCH /experiments/:id/allocation`) — bearer-token authed, includes LLM-generated
  variant content at creation time.
- **Results** (`GET /results/:id`) — exposures/conversions/rate per variant, a
  two-proportion z-test vs. control, and a Sample Ratio Mismatch integrity check.
- **Production snippet** (`public/snippet.js`) — the actual customer-facing
  integration: loads synchronously in `<head>`, hides the page before paint, applies
  variant content declaratively via `data-experiment-id`, and reveals on assignment
  or a configurable timeout (default 200ms, see DESIGN.md §4). `public/snippet-test.html`
  is a minimal page exercising it end to end (verified in a real browser: hide/reveal,
  DOM replacement, sticky visitor identity, exposure beacon).
- **Demo page** (`public/demo.html`, served at `/demo.html`) — a separate, narrated
  manual test harness with its own inline JS and visible logging, for walking through
  the API step by step. Not what a real integration would use — that's the snippet above.
- **Shared tab bar** (`public/nav.js`) — a small dependency-free script included at the
  top of `<body>` on the experiments, demo, and snippet-test pages, so they all link to
  each other with the current page highlighted.
- **Experiments admin page** (`public/experiments.html`, served at `/experiments.html`)
  — lists experiments via `GET /experiments` (bearer token entered in the page, kept in
  `localStorage` only) and expands a row to show its `GET /results/:id` breakdown
  (exposures/conversions/rate, significance vs. control, SRM flag). "+ New experiment"
  opens a form (`POST /experiments`, optionally `POST /sites` first if you don't have a
  site key yet) with a per-variant "% traffic" field — e.g. Control 80%, two variants at
  10% each — that must sum to 100% and is converted into contiguous bucket ranges
  live as you type. Each variant's copy can be typed by hand or generated by the LLM
  (`generate: {prompt}`, DESIGN.md §7) — the request blocks until generation finishes,
  per the same design. "Edit allocation" on an existing experiment (`GET
  /experiments/:id` to load current ranges, percent fields to set a new split) works out
  the minimal ordered sequence of single-boundary `PATCH /experiments/:id/allocation`
  calls needed to reach it and fires them one at a time — since the endpoint only allows
  moving one shared boundary per call (DESIGN.md §2), reallocating control's traffic
  across two or more variants takes more than one request under the hood. Adding,
  removing, renaming, or changing content isn't offered here, matching what the API
  actually allows — that's a new experiment (new salt) instead.

## Stack

Node/TypeScript, Fastify, Postgres via Drizzle ORM, Anthropic API for LLM-generated
variant copy. Reasoning for each choice is in `DESIGN.md` §9.

## Local setup

Requires Node 20+ and a Postgres instance.

```bash
npm install
cp .env.example .env   # fill in DATABASE_URL, CONFIG_API_TOKENS, ANTHROPIC_API_KEY

npm run db:generate    # only needed after changing src/db/schema.ts
npm run db:migrate     # applies migrations/ to DATABASE_URL

npm run dev            # starts the API on http://localhost:8080
```

Open `http://localhost:8080/demo.html` — it will report "no experiment configured"
until you create a site and an experiment (see below).

## Exercising the API

```bash
# 1. Register a site, get back its public key
curl -X POST http://localhost:8080/sites \
  -H "Authorization: Bearer $CONFIG_API_TOKENS" -H "Content-Type: application/json" \
  -d '{"name":"my site"}'

# 2. Create an experiment. Mark a variant `"generate": {"prompt": "..."}` instead of
#    `"content"` to have its copy written by the LLM at creation time (DESIGN.md §7).
curl -X POST http://localhost:8080/experiments \
  -H "Authorization: Bearer $CONFIG_API_TOKENS" -H "Content-Type: application/json" \
  -d '{
    "id": "demo-headline",
    "siteKey": "<key from step 1>",
    "name": "Demo Headline Test",
    "variants": [
      {"id": "control", "name": "Control", "rangeStart": 0, "rangeEnd": 4999, "isControl": true, "content": {"text": "Welcome!"}},
      {"id": "b", "name": "Variant B", "rangeStart": 5000, "rangeEnd": 9999, "generate": {"prompt": "a short, punchy signup call-to-action"}}
    ]
  }'

# 3. Ask for an assignment (waits up to CONFIG_POLL_INTERVAL_MS for the new
#    experiment to reach the in-memory cache — see DESIGN.md §1, "fleet staleness window")
curl "http://localhost:8080/assign?visitorId=visitor-1&siteKey=<key>&experiments=demo-headline"

# 4. Track what happened
curl -X POST http://localhost:8080/track/exposure -H "Content-Type: application/json" \
  -d '{"visitorId":"visitor-1","siteKey":"<key>","experimentId":"demo-headline","variantId":"control"}'
curl -X POST http://localhost:8080/track/conversion -H "Content-Type: application/json" \
  -d '{"visitorId":"visitor-1","siteKey":"<key>","experimentId":"demo-headline","goalId":"signup"}'

# 5. See results
curl http://localhost:8080/results/demo-headline
```

## Deployment

Deployed on Fly.io — see `Dockerfile` and `fly.toml`. Migrations run as the release
command, once per deploy, before new instances take traffic.

```bash
fly launch    # picks a region, wires up fly.toml — rename the app first
fly secrets set DATABASE_URL=... ANTHROPIC_API_KEY=... CONFIG_API_TOKENS=...
fly deploy
```
